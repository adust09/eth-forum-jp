## 動機

私たちは、クロスベニューの市場ミクロ構造に関する狭い問いを調査しています。

**中央集権型取引所 (CEX) におけるBTCおよびETHの無期限取引から生成された予測シグナルは、イーサリアムベースの分散型取引所 (DEX) で流動性が提供される際に、逆選択を減らすことができるか？**

私たちは、CEXでの収益性の高い構築物 (construct) がDEXに単純にコピーできるとは考えていません。私たちの初期の前提は意図的に懐疑的です。ソースシグナルが有益であったとしても、以下の理由により優位性 (edge) が失われる可能性があります。

-   ソースフィードとネットワークの遅延
-   注文の構築と署名
-   ゲートウェイ、[[glossary/sequencer|シーケンサー]]、またはブロックのタイミング
-   異なるマッチングおよび価格形成ルール
-   [[glossary/MEV|MEV（最大抽出可能価値）]]とトランザクション順序付け
-   手数料と流動性の断片化
-   キューポジション、約定漏れ、キャンセル競争
-   ベニュー間での異なる参加者行動

私たちは、以前の価格変動方向を制御した後でも、いくつかの固定モデル出力に短期的な情報が含まれているというソースベニューの証拠を持っています。その情報が、別のベニューでの実行を改善するのに十分な期間存続するかどうかは、まだ分かっていません。

提案された実験に対する批判、特に[[glossary/MEV|MEV]]、[[glossary/Orderflow|オーダーフロー]]、DEX実行、[[glossary/sequencer|シーケンサー]]、マーケットメイキングに取り組んでいる研究者からの意見を歓迎します。

## ソースストリームとプロダクションパス

ソースストリームは、中央集権型取引所 (CEX) からのBTCUSDTおよびETHUSDTの無期限取引で構成されています。

同価格の取引は決定イベントから除外されます。残りの各イベントは価格変動取引です。各イベントで、プロダクションエンジンは次のことを行います。

1.  そのイベントで利用可能な情報のみを使用して因果的特徴量 (causal features) を更新します。
2.  方向性、反転、スイングモデルファミリーを評価します。
3.  `dir_mr`と呼ばれる固定の方向性保護構築物 (directional-protection construct) を更新します。
4.  ソース市場のタイムスタンプ、生成タイムスタンプ、モデル出力、構築物の状態を記録します。
5.  評価のためだけに、その後の価格変動を観測します。

プロダクションパスはRust/C++で実装されています。ローカル推論には、モデルファミリーに応じて約**4～50マイクロ秒**かかります。

これはローカル推論時間であり、エンドツーエンドの実行遅延ではありません。以下は含まれません。

-   取引所公開遅延
-   市場データ転送
-   クロスベニュー伝播
-   注文の構築と署名
-   宛先ゲートウェイの確認応答
-   [[glossary/sequencer|シーケンサー]]またはブロックへのインクルージョン
-   最終決済

この区別は実験の中心です。注文が宛先ベニューで実行可能になる前に情報が陳腐化する場合、マイクロ秒単位の推論パスは経済的に無関係です。

## `dir_mr`構築物の厳密なセマンティクス

`dir_mr`は、以下の3つの状態を持つイベント駆動型ステートマシンです。

\[
q\_t \in \{-1,0,+1\},
\]

ここで：

-   (q\_t=0): アクティブな方向性保護状態なし
-   (q\_t=+1): アクティブなロング/上昇状態
-   (q\_t=-1): アクティブなショート/下降状態

この構築物は以下を組み合わせます。

-   **方向性ロング/ショートシグナル**：方向性状態を開始します。
-   **反転シグナル**：アクティブな方向性の枯渇または反転の可能性を特定します。
-   **スイングシグナル**：反対の平均回帰またはスイング状態を特定します。

遷移ルールは固定されています。

### 状態の開始

-   フラットな場合、有効な**ロング**方向性シグナルは (q\_t=+1) を開始します。
-   フラットな場合、有効な**ショート**方向性シグナルは (q\_t=-1) を開始します。
-   `reversal`と`swing`は、独立して`dir_mr`状態を開始することは**ありません**。

### ロング状態の終了

アクティブなロング状態は、以下のいずれかが発生した場合に終了します。

-   有効なショート方向性シグナル
-   ロング状態に反する反転シグナル
-   ロング状態に反するスイングシグナル
-   ハードタイムアウト

擬似コード：

```
if state == FLAT:
    if long_signal:
        state = LONG
    elif short_signal:
        state = SHORT

elif state == LONG:
    if short_signal or reversal_down or swing_down or timeout:
        state = FLAT

elif state == SHORT:
    if long_signal or reversal_up or swing_up or timeout:
        state = FLAT
```

状態は、固定された実時間間隔で保持されるのではなく、イベント駆動型です。反対の条件がいつ到達するかによって、観測される状態は数ミリ秒から数分間続くことがあります。

## これが逆選択制御に役立つ可能性のある理由

`dir_mr`は、トリガーされたすべての状態が直接実行可能な方向性戦略であることを証明することを意図していません。その提案された実行用途はより狭く、差し迫った不利な動きに対して、パッシブな流動性のどちら側がより晒されているかを判断することです。

例えば：

-   アクティブな上昇状態中、パッシブなアスクは、市場がさらに上昇する直前に約定する可能性があるため、有害である可能性があります。
-   アクティブな下降状態中、パッシブなビットは、市場がさらに下降する直前に約定する可能性があるため、有害である可能性があります。
-   反対側のクォートサイドは、在庫と約定の制約にもよりますが、より有利なその後のマークアウト (markout) を持つ可能性があります。

このマッピングは、宛先ベニューでの約定でテストされるべき仮説です。ソース市場の方向性の正しい予測は、それ自体がDEX注文が約定し、有害性を回避し、正の純損益 (P&L) を生み出すことを証明するものではありません。

## ソースベニューの結果

現在のCEXのみの概念実証では：

| 銘柄 | 構築物 | 総損益/取引 | 取引勝率 (Trade WR) | 生リターンIC | モメンタム制御部分IC | カバレッジ |
| --- | --- | --- | --- | --- | --- | --- |
| BTCUSDT 無期限 | dir_mr | +0.82 bps | 76.4% | +0.525 | +0.394 | 2.4% |
| ETHUSDT 無期限 | dir_mr | +0.95 bps | 69.5% | +0.606 | +0.160 | 3.6% |

`Trade WR`は、評価された`dir_mr`状態のうち収益性のあるものの割合であり、すべてのソースイベントにおける方向性精度ではありません。`Coverage`は、評価定義の下で構築物がアクティブまたはトリガーされる適格なソースイベントの割合です。

これらは、**手数料、スプレッド、キューポジション、拒否された注文、約定漏れ、クロスベニュー遅延を考慮する前の総ソースベニュー結果です。DEXの損益 (P&L) を実証するものではありません。**

ソースメトリクスは、クロスベニューで反証を試みる価値のある固定された関係があることを確立するために含まれています。宛先実験は、DEXの結果を観測した後にモデルの方向性、閾値、または終了セマンティクスを調整すべきではありません。

## ティックモメンタムベースラインの制御

価格変動取引ストリームには、強い継続コンポーネントが含まれています。モデルは、以前の価格変動の符号を再現するだけで予測性があるように見えることがあります。

したがって、私たちは素朴なソースベースラインを使用します。

\[
m\_t=\operatorname{sign}(\Delta P\_t)
\]

そして、両側から以前の価格変動の符号を制御する部分スピアマン相関を計算します。

\[
\rho\_{\text{model},\text{forward}\mid\text{previous}} = \frac{
\rho\_{ms}-\rho\_{mp}\rho\_{sp}
}{
\sqrt{(1-\rho\_{mp}^{2})(1-\rho\_{sp}^{2})}
}.
\]

ここで：

-   ($\rho\_{ms}$) は、モデルスコアと将来の符号付きリターンとの間のスピアマン相関です。
-   ($\rho\_{mp}$) は、モデルスコアと以前の価格変動の符号との間の相関です。
-   ($\rho\_{sp}$) は、将来の符号付きリターンと以前の価格変動の符号との間の相関です。

部分ICがゼロに近い場合、モデルが主にモメンタムプロキシであることを示唆します。正の部分ICは、このランク線形関係を除去した後の増分ランク情報を示します。

代表的なソースストリームの結果は次のとおりです。

| モデルファミリー | h=1 | h=3 | h=5 | h=10 |
| --- | --- | --- | --- | --- |
| hh_step1_updwn | 0.136 | 0.104 | 0.084 | 0.059 |
| lh_v4_step1_updwn | 0.210 | 0.167 | 0.130 | 0.081 |
| roc2_step1_updwn | 0.462 | 0.364 | 0.283 | 0.183 |
| roc3_updwn | 0.349 | 0.280 | 0.218 | 0.142 |
| ha_roc1_step1_updwn | 0.424 | 0.335 | 0.262 | 0.170 |

ホライズン (h) は、その後の価格変動イベントで測定されます。これらの値は部分スピアマンICであり、精度や実行可能な損益 (P&L) ではありません。

私たちは、(|IC|>0.05) のような任意の大きさを有意性検定として解釈しません。正式な推論では、系列依存性、重複するホライズン、モデルの多重性、レジームの不安定性を考慮する必要があります。

## CEXからDEXへの転送が失敗する可能性のある理由

### 1. 転送中のシグナル減衰

以下とします。

\[
t\_s=\text{ローカルシグナル生成時間}
\]

および：

\[
t\_e=\text{アクションが宛先ベニューで実行可能になる時間}.
\]

経済的に関連する遅延は次のとおりです。

\[
L=t\_e-t\_s.
\]

完全なパスには以下が含まれる場合があります。

\[
L =
L\_{\text{feed}}
+L\_{\text{network}}
+L\_{\text{inference}}
+L\_{\text{signing}}
+L\_{\text{gateway}}
+L\_{\text{sequencer/block}}.
\]

条件付きリターンがこのパスよりも速く減衰する場合、統計的に強力なソースシグナルは経済的に無用になります。

したがって、主要な分析には、1つの遅延仮定ではなく、遅延曲線を含める必要があります。

\[
\operatorname{Edge}(L), \qquad
L\in\{0,1,5,10,25,50,100,250,500\text{ ms},1\text{ s},1\text{ block}\}.
\]

### 2. 異なる宛先メカニズム

CEXの中央指値注文板、AMM（自動マーケットメイカー）、RFQ（見積もり依頼）システム、およびオンチェーン決済を伴うオフチェーン注文板は、異なる経済状態を露出させます。

中央指値注文板の宛先の場合、関連する結果には以下が含まれる場合があります。

-   約定確率
-   キュー調整後の約定後マークアウト
-   手数料控除後のスプレッド獲得
-   キャンセル成功
-   在庫調整後損益 (P&L)

AMMの宛先の場合、より適切な結果には以下が含まれる場合があります。

-   LPマークアウト
-   [[glossary/Loss-Versus-Rebalancing|リバランス損失 (LVR)]]
-   裁定取引損失
-   在庫の置き換え
-   スワップ後のCEX-DEX収束

同じソースシグナルを、互換性のないベニュー設計間で同一の実行メトリクスで判断すべきではありません。

### 3. 機械的な価格リーダーシップ

正の転送結果は、普遍的なクロスベニュー予測を表すものではないかもしれません。宛先は以下を使用する可能性があります。

-   CEXに影響されたオラクル
-   ソース取引所を含むインデックス
-   同じソースを監視する裁定取引者
-   ソースベニューでヘッジを行うマーケットメイカー

実験は、独立した予測と機械的なソースベニューのリーダーシップを区別すべきです。後者も経済的に有用である可能性がありますが、それは異なる主張です。

### 4. 約定選択とキャンセル競争

ソースパフォーマンスはソースイベントに条件付けられます。宛先パフォーマンスは、注文が提出され、確認応答され、約定されるかどうかに条件付けられます。

中間価格シミュレーションは有利に見えるかもしれませんが、以下の場合には失敗します。

-   キューポジション
-   ポストオンリー拒否
-   部分約定
-   キャンセル遅延
-   ガス代とプロトコル手数料
-   最も情報量の多いイベント中の約定漏れ
-   在庫蓄積

したがって、主要な結果は、その後の中間価格方向だけでなく、実際のまたは現実的にシミュレートされた宛先約定に条件付けられたマークアウトであるべきです。

### 5. MEVと順序付け

公開イーサリアムベニューでは、提出されたアクションが意図を明らかにする可能性があります。それは以下の可能性があります。

-   並べ替えられる
-   サンドイッチされる
-   優先順位を奪われる
-   予測された動きの後にのみ含まれる
-   実行が有利であった場合に除外される

プライベート[[glossary/Orderflow|オーダーフロー]]とプライベート[[glossary/sequencer|シーケンサー]]は、一部のリスクを軽減する一方で、異なる信頼、検閲、[[glossary/Data-Availability|データアベイラビリティ]]の仮定を導入する可能性があります。

### 6. クロック同期と隠れた先読み

CEX取引所時間、ローカル受信時間、モデル時間、宛先ゲートウェイ時間、[[glossary/sequencer|シーケンサー]]時間、イーサリアムブロック時間は異なるクロックです。

防御可能な記録には以下が含まれるべきです。

-   ソース取引所タイムスタンプ
-   ローカルソース受信タイムスタンプ
-   ローカルモデル生成タイムスタンプ
-   注文構築および提出タイムスタンプ
-   宛先確認応答タイムスタンプ
-   約定またはインクルージョンタイムスタンプ
-   宛先市場状態タイムスタンプ

これらのフィールドがないと、モデル自体が因果的であっても、クロスベニューの結果に隠れた先読みが含まれる可能性があります。

## 提案された反証実験

宛先結果が検査される前に、ソース構築物は凍結されるべきです。

-   固定されたソースモデル
-   固定されたモデルの方向性
-   固定された`dir_mr`遷移
-   固定されたソース閾値
-   固定された宛先アクションマッピング
-   事前に宣言された遅延とマークアウトホライズン

すべてのソースイベントについて：

1.  ソース取引所、ローカル受信、生成タイムスタンプを記録します。
2.  提出前に観測可能な最新の宛先状態を記録します。
3.  事前定義された宛先アクションを提出またはシミュレートします。
4.  提出、確認応答、キャンセル、約定イベントを記録します。
5.  固定されたイベント時間および実時間ホライズンで宛先結果を測定します。
6.  明示的な人工遅延の下で結果を再計算します。
7.  因果的な宛先認識ベースラインと比較します。

提案される制御変数には以下が含まれます。

-   以前のソース価格変動の符号
-   ソースと宛先のモメンタム
-   ソースと宛先の[[glossary/Orderflow|オーダーフロー]]不均衡
-   実現ボラティリティ
-   宛先スプレッドと利用可能な板の厚さ
-   CEX-DEXベーシス
-   オラクル更新タイミング
-   ガス価格
-   ブロックまたは[[glossary/sequencer|シーケンサー]]ポジション
-   時刻
-   ファンディングおよび清算イベント

主要な増分テストは次のとおりです。

\[
\operatorname{Outcome}\_{DEX}
\sim
\text{宛先制御変数}
+
\text{CEX制御変数}
+
\text{固定されたソースシグナル}.
\]

関連する問いは、ソースシグナルが後のDEX価格と相関するかどうかではありません。それは、**固定された**ソースシグナルが、宛先で既に観測可能な情報を超えて、実行に関連する宛先結果を改善するかどうかです。

## 公開された時点記録

ソース記録は、公開された読み取り専用のバージョン管理されたAmazon S3アーカイブに非同期にミラーリングされます。

ブラウザリストは次のとおりです。

[https://finaipub.s3.ap-southeast-1.amazonaws.com/?list-type=2&prefix=signals/](https://finaipub.s3.ap-southeast-1.amazonaws.com/?list-type=2&prefix=signals/)

オブジェクト構造は次のとおりです。

```
signals/{symbol}/{engine_session}/{generation_timestamp}.json
```

例：

```
signals/BTCUSDT/20260629_104323/1782730034703.json
```

ここで：

-   `symbol`はソース銘柄です。
-   `engine_session`は連続したプロダクションエンジンセッションを識別し、再起動やデプロイメントを区別します。
-   `generation_timestamp`は、ある時点のイベント記録を識別します。

各イベントオブジェクトには、利用可能なタイムスタンプ、個々のモデル出力、派生シグナル、およびソース側のシーケンスを再構築するために必要な構築物の状態が含まれています。`dir_mr`の状態は上記の遷移ルールを使用して解釈する必要があります。方向性ロング/ショートシグナルは状態を開始し、反対方向のシグナル、反対の反転、反対のスイング、またはタイムアウトによって状態が閉じられます。

完全な公開アーカイブは、AWSアカウントなしでダウンロードできます。

```
aws s3 sync s3://finaipub/signals/ \
  ./finai-signals/ \
  --no-sign-request
```

アーカイブは通常、ローカルシグナル生成後**150～200ミリ秒**で公開されます。これはアップロードが非同期であるためです。これは実行パスの一部ではなく、低遅延フィードとして使用すべきではありません。

アーカイブは、ある時点での検査と独立した再構築のために存在します。S3のバージョン履歴と個別の市場および生成タイムスタンプにより、後の変更が観測可能になります。これが十分な研究の来歴 (provenance) であるか、または記録をさらにハッシュチェーンし、定期的にイーサリアムに[[glossary/anchoring|アンカリング]]すべきかについて、フィードバックを歓迎します。

制御された再現に興味のある研究者は、独立した非営利評価のために、読み取り専用の履歴抽出または研究ストリームを無料でリクエストすることもできます。
