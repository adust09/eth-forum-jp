## 要旨

イーサリアムの公開P2Pおよび[[glossary/Data-Availability|データアベイラビリティ (DA)]]層を介して、プライベートスマートコントラクト、機密性の高いL2/[[glossary/Validium|Validium]]ステート差分、またはパーミッション付きインテントペイロードを展開・配布することは、現在、根本的なメタデータボトルネックに直面しています。コントラクトのバイトコードやステートが対称暗号化されている場合でも、既存の[[glossary/Broadcast-Encryption|ブロードキャスト暗号 (BE)]]および[[glossary/Attribute-Based-Encryption|属性ベース暗号 (ABE)]]スキームでは、承認された受信者インデックス、カバーするサブセット、またはターゲットアクセスツリーを指定する明示的なクリアテキストヘッダーを添付する必要があります。

この投稿では、イーサリアム上でのプライベートコントラクトと暗号化されたステートのゼロメタデータ配信のために、[[glossary/BLS12-Curves|BLS12-381]]上の**[[glossary/Stealth-ABBE|ステルス属性ベースブロードキャスト暗号 (Stealth ABBE)]]** ([Zenodo Preprint](https://doi.org/10.5281/zenodo.23677112)) に基づくアーキテクチャフレームワークを提案します。指数[[glossary/exponential-ElGamal|エルガマル暗号文]] (𝔾1 × 𝔾1) におけるキャリーフリーBase-3パッキングを用いた𝔽256上の**[[glossary/homomorphic-blind-Reed-Solomon-decoding-problem|準同型ブラインドリード・ソロモン復号問題]]**としてブロードキャストアクセス制御を再定式化することで、Stealth ABBEは以下を達成します。

1.  **[[glossary/O1-Broadcast-KEM-Size|O(1)ブロードキャストKEMサイズ]] (償却済み24.1 KiB):** 総参加者数 *N* にかかわらず、単一の[[glossary/blob|EIP-4844ブロブ]]（128 KiBブロブの約19%）に余裕を持って収まります。
2.  **ゼロ可視ヘッダーまたは取り消しリスト (0バイト):** アクセスポリシー、コホート名簿、および取り消しステートは、非系統[[glossary/ReedSolomon-codes|リード・ソロモン符号]]のコードワードに代数的に吸収されます。
3.  **一様なノイズ不可分性 (STACパラダイム):** 𝔾1上の明示的な定数時間逆同種写像と[[glossary/Elligator-Squared|エリゲーター・スクエアード]]を使用することで、ブロードキャストフレーム全体が一様なチャネルノイズと統計的に区別できなくなり、[[glossary/Mempool|メムプール]]/ブロブの[[glossary/Deep-Packet-Inspection|ディープパケットインスペクション (DPI)]]やコホートグラフ分析を無効にします。
4.  **ゼロ通信エポック内取り消し:** 侵害されたノードや監査者は、アクティブな参加者の鍵を再設定することなく、*O*(1)で即座に排除できます。

## 動機：プライベートコントラクト配信におけるメタデータ漏洩問題

エンタープライズコンソーシアム、プライバシー保護[[glossary/Rollup|ロールアップ]]（[[glossary/Validium|Validium]] / [[glossary/Plasma|Plasma]]）、または機関向けDeFiプロトコルが、[[glossary/Ethereum-Transparency-Layer|イーサリアム]]を決済およびDA層として使用して、動的な承認済み実行ノード、シーケンサー、または監査者のコホートに**[[glossary/private-smart-contract|プライベートスマートコントラクト]]** *M*（プロプライエタリな[[glossary/EVM|EVM]]/[[glossary/EOF-bytecode|EOFバイトコード]]、機密性の高い[[glossary/ABI-parameters|ABIパラメータ]]、または[[glossary/zero-knowledge-circuit-witnesses|ゼロ知識回路証人]]を含む）を展開・配布したいとします。

ブロードキャスターが *C**M* = SymEnc*κ̂*(*M*) をコールデータまたは[[glossary/blob|EIP-4844ブロブ]]を介して公開する場合、一時的なセッションキー *κ̂* をどのように配布するのでしょうか？

-   **素朴な多受信者暗号化:** *κ̂* を *N* 個の受信者公開鍵に個別に暗号化すると、*O*(*N*) のスケーリングとなり、コホートの正確なサイズとID/鍵が露出します。
-   **古典的ブロードキャスト暗号 (NNL, BGW) およびペアリングABBE:** BGWは*O*(1)のグループ要素を達成しますが、受信者が復号積を計算できるように、正確な承認済みインデックスセット *S* をクリアテキストで送信することを義務付けています。同様に、ペアリングベースのABEスキームはアクセスポリシーツリーをクリアテキストで露出し、脆弱なブール論理に悩まされます。
-   **動的取り消しボトルネック:** 標準スキームで侵害された[[glossary/Ethereum-validator|バリデータ]]または未承認ノードを排除するには、ヘッダーの肥大化 *O*(*r* log(*N*/*r*)) または高価なグローバルな鍵の再設定のいずれかが必要です。

**目標:** ブロードキャスターがイーサリアム上に単一の定数サイズの暗号化されたブロブまたはトランザクションペイロードを投稿し、以下の条件を満たすことを目指します。

1.  暗号的にプロビジョニングされた属性が *k*\-out-of-*n*閾値ポリシーを満たすノードのみが *κ̂* を復元し、[[glossary/private-smart-contract|プライベートコントラクト]] *M* をインスタンス化できること。
2.  外部の観測者（[[glossary/Searcher|MEVサーチャー]]、検閲されたリレー、または受動的なチェーンアナリスト）には、ゼロのクリアテキストヘッダー、ゼロの可視ポリシー、ゼロの取り消しリストを持つ**一様なランダムバイト**が見えること。
3.  ネイティブのイーサリアム暗号技術（[[glossary/EIP|EIP]]-[[glossary/EIP-2537|2537]]を介した[[glossary/BLS12-Curves|BLS12-381]]）が全体に活用されていること。

## コアメカニズム：イーサリアム上でのステルスABBEの仕組み

組み合わせサブセットツリーや明示的なペアリングアクセスツリーの代わりに、Stealth ABBEはアクセス制御を、𝔽256上の**[[glossary/non-systematic-Reed-Solomon-code|非系統リード・ソロモン (RS) コード]]** *C*RS\[256, 192, 65\]256（レート *R* = 0.75、一意なシンドローム復号半径 ℵ = 31シンボルエラー）の誤り訂正能力に直接埋め込みます。

### 1. 分散型セットアップ（BLS12-381上のDKG/MPC）

分散型[[glossary/Multi-Authority-Federation|多機関連合]] *F*（例：L2委員会、[[glossary/EigenLayer-AVS|EigenLayer AVS]]、または閾値[[glossary/DAO|DAO]]）は、BLS12-381（素数位数 ℓ の *e* : 𝔾1 × 𝔾2 → 𝔾*T*）上で[[glossary/DKG|分散鍵生成 (DKG)]]プロトコルを実行します。

-   グローバルマスターシークレット *α* ∈ ℤℓ\* はクリアテキストで再構築されることはありません。公開暗号化鍵は *P*pub = \[*α*\]*G*1 ∈ 𝔾1 です。
-   各承認済みノード/参加者 U*j* は独立した秘密鍵 *S*U,*j* = \[*sk**j*\]*G*2 を保持し、[[glossary/Key-Escrow|鍵エスクロー]]なしで不変条件 *S*U,*j* + *H**j* = \[*α*\]*G*2 を満たす[[glossary/oblivious-extraction-helper|秘匿抽出ヘルパー]] *H**j* = \[*α* − *sk**j*\]*G*2 を受け取ります。
-   各参加者には、複合マスク属性ベクトルをカプセル化するローカルに保存された**[[glossary/ElGamal-Encrypted-Access-Code|エルガマル暗号化アクセスコード]]** *C*U,*j* ∈ (𝔾1 × 𝔾1)*N*blk がプロビジョニングされます。

> **M***j* = (**w** ∥ **r***j*) + **m** ∈ 𝔽256256

ここで、**w** ∈ 𝔽256128 は[[glossary/high-weight-cohort-isolating-blocker|高重みコホート分離ブロッカー]] (wt(**w**) > ℵ)、**r***j* ∈ 𝔽256128 は参加者の属性ベクトル、**m** ∈*R* 𝔽256256 は[[glossary/information-theoretic-one-time-blinding-pad|情報理論的ワンタイムブラインディングパッド]]です。

### 2. 𝔾1におけるキャリーフリーBase-3パッキング

ブロードキャスト暗号文と *C*U,*j* を結合する際に、マスク **w** と **m** を準同型的にキャンセルするために、𝔾1上の加法準同型[[glossary/ElGamal-ciphertexts|エルガマル暗号文]]の指数内部でビット単位XOR（𝔽256加算）が必要です。コンポーネントごとのエルガマル加算は、ℓを法とする整数加算を評価するため（二進数の1 + 1 = 2はビット間でキャリー破損を引き起こします）、**[[glossary/superincreasing-Base-3-weights|超増加型Base-3重み]]**を使用して *η*\-ビットブロック（*η* = 8, *N*blk = 256）を埋め込みます。

> *W**η*(**x**) = ∑*u*\=1..*η* *x**u* · 3*u*−1 ∈ \[0, 3*η* − 1\]

2つの二進ベクトルがエルガマル指数で加算されるとき、各三進数桁は *γ**u* = *x**u* + *y**u* ∈ {0, 1, 2} < 3 を満たします。トリット間キャリーは発生せず、正確なXOR和は *R**η*(*Z*) = ((⌊*Z* / 3*u*−1⌋ mod 3) mod 2)*u*\=1..*η* を介して決定論的に復元されます。

### 3. **モノリシックプライベートコントラクトのカプセル化とブロードキャスト:**

プライベートコントラクト *M* をデプロイまたは更新するには：

-   **[[glossary/Symmetric-Encryption|対称暗号化]]:** ブロードキャスターはコントラクトのバイトコードとステートを暗号化します: *C**M* = SymEnc*κ̂*(*M*)。そして、オンチェーンコミットメント（例：コードハッシュ + ステートルート）をイーサリアムのレジストリコントラクトに投稿します。
-   **[[glossary/Monolithic-KEM-Payload-Formulation|モノリシックKEMペイロードフォーミュレーション]]:** ブロードキャスターは、セッションキーとその暗号的バインディングメタデータを含む192バイト（1536ビット）のペイロードを構築します。
    
    > *κ* = *κ̂*256b ∥ *κ̃*256b ∥ *B*512b ∥ *σ**i*,128b ∥ Σ*i*,384b ∈ 𝔽256192
    
-   **[[glossary/non-systematic-RS-encoding|非系統リード・ソロモンエンコーディング]]:** *κ* は**非系統RSエンコーディング**を介して、コードワード **c** = EncodeRS(*κ*) ∈ 𝔽256256 にエンコードされます。これは、不正な参加者が左側の128バイトから行列の逆演算を実行するのを防ぐために、レート *R* = 0.75（192情報バイト + 64パリティバイト）で *δ* = 64バイトの[[glossary/MDS-puncturing-defense-margin|MDSパンクチャリング防御マージン]]を組み込みます。
-   **ポリシートークンマスキング:** コードワード **c** は、ポリシートークン **T***i* = (**w** ∥ **p***i*) + **m**（ここで **w** はコホートブロッカー、**p***i* はターゲット属性ポリシー、**m** はワンタイムブラインディングパッド）で代数的にマスクされ、ブラインドブロードキャストベクトルを生成します。
    
    > **c**′ = **c** + **T***i* ∈ 𝔔256256
    
-   **𝔾1におけるブロックごとの指数エルガマル暗号化:** メタデータの肥大化なしにベクトルを隠蔽するために、**c**′ はビットにシリアライズされ、キャリーフリーBase-3パッキングを使用して長さ *η* = 8ビットの *N*blk = 256ブロックに分割され、グローバル公開鍵 *P*pub = \[*α*\]*G*1 ∈ 𝔾1 の下で独立した一時的なスカラーを用いて加法準同型[[glossary/exponential-ElGamal|指数エルガマル]]でブロックごとに暗号化されます。
    
    > *C*(*t*) = (\[*r*bc(*t*)\]*G*1, \[*W**η*(**c**′(*t*)) mod ℓ\]*G*1 + \[*r*bc(*t*)\]*P*pub) ∈ 𝔾1 × 𝔾1
    
-   **[[glossary/STAC-Outer-Layer|STACアウターレイヤー]]とブロブ公開:** 𝔾1の各点は、明示的な定数時間逆同種写像と[[glossary/Elligator-Squared|エリゲーター・スクエアード]]を介して、𝔽*p*2 の一様なペア (*u*, *v*)（点あたり96バイト）にマッピングされます。結果として得られる**24.1 KiB**のKEMフレームは、[[glossary/blob|EIP-4844ブロブ]]に直接投稿されます。

### 4. 承認済みノードによるローカル抽出とブラインド復号

ブロブを取得すると、承認済みノード U*j* は以下を実行します。

1.  エリゲーター・スクエアードのフィールド要素を𝔾1にマッピングし、ローカルのアクセスコードを準同型的に加算します: *Ĉ**j*(*t*) = *C*(*t*) + *C*U,*j*(*t*)。
2.  双線形ペアリングを介して、各ブロックを円分部分群 𝔾*T* ⊂ 𝔽\**p*12 に射影します。

> *e*(*Ĉ**j*,2(*t*), *G*2) · *e*(*Ĉ**j*,1(*t*), −(*S*U,*j* + *H**j*)) = *g**T**Z*(*t* )

ここで、𝔾Φ12(*p*) ⊂ 𝔽\**p*12 における逆演算は、コストフリーなフロベニウス共役 *A*−1 = *A**p*6 = *Ā* です。

3.  L1/L2キャッシュ常駐の**64ビット[[glossary/Prefix-Lookup-Table|プレフィックスルックアップテーブル]]（合計131.2 KB）**を使用して**O(1)時間**で *Z*(*t*) ∈ \[0, 13120\] を抽出し、摂動されたコードワードを再構築します。

> **c**″ = **c** + (**0**128 ∥ (**p***i* + **r***j*))

**w** + **w** = **0** および **m** + **m** = **0** は標数2で自己消滅することに注意してください！

4.  定数時間[[glossary/Berlekamp-Massey-RS-decoding|バーレカンプ・マッセイRS復号]]を実行します。属性の不一致が wt(**p***i* + **r***j*) ≤ ℵ = 31 を満たす場合、U*j* は *κ̂* を復元し、*κ̃* と Σ*i* を検証し、[[glossary/private-smart-contract|プライベートコントラクト]] *M* を復号します。

## 即時O(1)取り消しと共謀耐性

侵害された[[glossary/Ethereum-validator|バリデータ]]または監査者 Urev を、他の全員の鍵を再設定したり、取り消しリストを公開したりすることなく、エポック途中でどのように取り消すのでしょうか？

-   **Tier-1 [[glossary/Cover-Free-Error-Budget-Shifting|カバーフリーエラーバジェットシフト]]:** 128バイトの右側属性ベクトル内で、*M* = 48バイトが取り消しサブブロックを形成します。各ノード U*j* には、ペアワイズ交差 |*W**j* ∩ *W**j*′| ≤ 4 のカバーフリー族から16バイトのクリーンウィンドウ *W**j* が割り当てられ、𝔽256\* の非ゼロオフセットで埋められたベースラインエラー重み *τ*coh = 27 ≤ 31 が設定されます。Urev を取り消すには、ブロードキャスターは *W*rev 内の12バイトを摂動させます。
    -   Urev の場合、エラー重みは 27 + 12 = 39 > *J*(128, 64) = 38 > ℵ = 31 に急増し、一意復号半径と[[glossary/Guruswami-Sudan-Grobner-basis-list-decoding-Johnson-bound|グルスワミ・スーダン/グロブナー基底リスト復号ジョンソン限界]]の両方を超えます！
    -   アクティブなメンバー U*j* の場合、少なくとも8バイトの摂動が「すでにエラー状態にある」座標に落ちるため（𝔽256\* で *ε* + *δ* ≠ 0、+0の新規エラーを追加）、エラー重みは ≤ 27 + 4 = 31 = ℵ に維持されます。
-   **二層アンチ共謀:**
    -   *偶数連合 (T* = 2): 2つのアクセスコードを合計すると、ターゲットマスク **w** と **m** は自己消滅しますが、2つのアクセスコードを **c**′ に加算すると、**w** と **m** はキャンセルされずに残ります（255/256エラー）。
    -   *奇数連合 (T* ≥ 3): 𝔾1で4つ以上の暗号文を合計すると、**[[glossary/Base-3-carry-avalanche|Base-3キャリーアバランシェ]]**（3 = 103, 4 = 113）がトリガーされ、256/256バイトが破損します。ペアが個別に𝔽256256に復号され、合計されたとしても、カバーフリー取り消しサブブロックは残余エラー重みを約43.8 > *J*(128, 64) = 38 に増幅させます。

完全なStealth ABBE鍵カプセル化フレームはわずか**24.1 KiB**しか必要とせず、単一の[[glossary/blob|EIP-4844ブロブ]]の**100 KiB以上**を、対称暗号化されたコントラクトバイトコード *C**M* と初期ステート差分を同じトランザクションで運ぶために利用可能です！

## イーサリアムのユースケースと議論のポイント

1.  **[[glossary/Private-Smart-Contract|プライベートスマートコントラクト]]配信（エンタープライズL2および[[glossary/Validium|Validium]]）:** L1上でコホートサイズ、参加者ID、ノード取り消しを明らかにすることなく、暗号化されたEVM/EOFバイトコードを動的な実行ノードセットに[[glossary/blob|EIP-4844ブロブ]]を介して配信します。
2.  **[[glossary/Encrypted-Mempool|ステルス暗号化メムプール]]とインテント/オーダーフローブロードキャスト:** 特定の担保/評判属性を持つソルバーのみがバンドルをブラインド復号できる、暗号化されたインテントまたはソルバーバンドルをブロードキャストします。[[glossary/Searcher|MEVフロントランナー]]向けのクリアテキストメタデータはゼロです。
3.  **最小限のオンチェーンアンカー（[[glossary/ERC-interface|ERCインターフェース]]）:** オンチェーンレジストリコントラクトは、*C**M* の32バイトのコミットメントハッシュ、現在のエポック番号、およびオプションで復号されたコントラクトステートに対する有効な実行の[[glossary/Zero-Knowledge-Proof|ZK証明]]を検証するだけで済みます。

ブロブ担保型Stealth ABBEコントラクトコンテナの最小限の[[glossary/ERC-interface|ERCインターフェース]]の標準化と、[[glossary/EIP-2537|EIP-2537]]プリコンパイルおよび[[glossary/L2-data-availability-committees|L2データアベイラビリティ委員会]]との統合の検討について、コミュニティからのフィードバックを歓迎します！
