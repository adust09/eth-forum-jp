オンチェーンで[[glossary/Autonomous-Agent|自律エージェント]]ができることを制限しようとすると、その質問に答えているように聞こえる[[glossary/ERC|ERC]]が多数見つかるでしょう。しかし、それらのほとんどは別の質問に答えています。どれがどれであるかを特定するのに1週間かかったので、信頼するのではなく確認できるように、その方法を添えてマップをここに示します。

これは誰かの仕事を批判するものではありません。以下の標準のいくつかは、私が探していたものを意図的に除外しており、その旨を明記しています。

### 方法

この分野ではタイトルが誤解を招くことがあります。「エージェント (agent)」、「委任 (delegation)」、「パーミッション (permission)」といった言葉が、互いに全く関係のない提案に登場します。そこで、私は内容に基づいてコーパスをランク付けしました。

`ethereum/ERCs` 内のすべての[[glossary/ERC|ERC]]がリストアップされ（**611ファイル**）、そのうち**7000以上**の番号を持つもの（**271ファイル**）が残され、その**全文**（約5.1 MB）がダウンロードされ、11の概念パターン（委任、減衰、サブエージェント、継承、上限、取り消し、有効期限、アイデンティティ、[[glossary/AI-agents|AIエージェント]]、注意事項、セッション）に対してスコア付けされました。そのランキングの上位は、要約ではなく、仕様書と議論スレッドを含め**端から端まで読み込まれました**。5つのスレッド、73件の投稿です。

このランキングはフィルターであり、評決ではありません。ERC-7303は3位でしたが、これは**誤検知 (false positive)** であり、エージェントとは関係のないトークンベースのロールアクセス制御です。

**スコープの制限は事前に明記されています。** コーパスは**マージされた** `ethereum/ERCs` ツリーです。オープンなプルリクエストやフォーラムのみのドラフトは含まれていません。[[glossary/ERC|ERC]]-8165（PR #1549、2月からオープン）はその一例であり、このレイヤーではなくインテント/ソルバー層に位置しています。

要約から誤解しやすい3つのこと：

**8273はセッションシステムではありません。** そのテキストには「有効期限メカニズムはなく、長期またはセッションベースの[[glossary/Attestation|アテステーション]]もありません」とあります。承認は1つのトランザクションに対してのみ存在します。コールを超えて存続する状態が必要な場合、これは間違った軸であり、正しい軸の弱いバージョンではありません。

**7710は注意事項を規定していません。** この[[glossary/ERC|ERC]]は1つの関数です。注意事項の強制、委任チェーン、取り消しは、そのリファレンス実装である*MetaMask Delegation Framework*の機能としてのみ登場します。この標準はまた、取得をスコープ外と宣言しています：「デリゲートが委任を取得するプロセスは意図的にスコープ外とされています。」そのセキュリティに関する考慮事項セクションは現在 `Needs discussion. <!-- TODO -->` で終わっています。

**8196は[[glossary/Final|ファイナル]]です。** それについてどう思おうと、変更されることはありません。

### 空の四角

271の標準のどれも、**減衰再委任 (attenuated re-delegation)** を標準化していません。これは、子エージェントが親によってすべての条項においてすでに制限された状態で存在し、その制限が剥奪不可能であるというものです。

最も近い候補は[[glossary/ERC|ERC]]-8226ですが、なぜそれが違うのかを正確に説明する価値があります。そのマンデートは `(agent, principal)` でキー付けされており、プリンシパルのみが許可できます。有効なマンデートを持つエージェントは何も作成できません。そのリファレンス実装で血統の語彙を検索すると —

```
grep -rniE "child|parent|sub-?agent|inherit|lineage|spawn|attenuat" contracts/ test/
```

— `@inheritdoc` というSolidityドキュメンテーションタグのみが返されます。この概念は、散文からだけでなく、コードからも欠落しています。

**これは欠陥ではありません。** [@thamerdridi](https://ethereum-magicians.org/u/thamerdridi)は私のスレッドで直接その点を指摘し、それは正しかったです。生成された子エージェントはRAMSの下では*行動する権限を含め*何も継承しないため、再生産をマンデートを回避するために使用することはできません。継承は設計上スコープ外です。正直な表現は「[[glossary/ERC|ERC]]-8226はマンデートの継承を定義しない」であり、「[[glossary/ERC|ERC]]-8226はバイパスできる」ではありません。

他のものにも同じ注意が適用されます。8199は、セッションキー方式のアプローチが「本質的にパーミッション回避の問題を引き起こす」と主張し、原則として粒度の細かい共有を拒否しています。8273は構築上トランザクションスコープです。7715はリクエストプロトコルであり、執行レイヤーではありません。これらはどれも手落ちではなく、4つの異なる質問に対する4つの異なる答えです。

この四角が空なのは、誰もそれを主張しなかったからであり、誰もが見落としたからではありません。

```
curl -sL https://raw.githubusercontent.com/ethereum/ERCs/master/ERCS/erc-8226.md
curl -s "https://ethereum-magicians.org/t/28208.json?include_raw=true&print=true"
```
